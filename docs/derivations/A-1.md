# A-1: Reusing pooled CLIP projections for local tokens

Issue: #16 (internal).
Scope: the approximation in [MATH_SPEC §1](../MATH_SPEC.md), its limited
justification, and a proposed validation-only alternative. This is a design
argument and experiment plan, not evidence of an empirical gain. Every claim
is numbered; checked sources are linked and unchecked assertions are marked.

## 1. What the projection was trained to do

**Claim A1.1 (verified source and precise terminology).** In the reference
[CLIP implementation](https://github.com/openai/CLIP/blob/main/clip/model.py),
`VisionTransformer.forward` applies the final visual LayerNorm and projection
to the CLS state, while `encode_text` applies the text projection to the EOS
(EOT in that code) state after final LayerNorm. The two projections are
**separate**: visual projection was trained on CLS outputs, text projection
on EOS outputs. The phrase “trained only on CLS and EOS” refers to these
respective readouts, not to one shared matrix or to the absence of training
signal in other tokens. Other tokens can affect a pooled representation
through attention. The projection's direct pretraining use is nevertheless
on pooled states, not a loss requiring each projected patch/word to align.

**Claim A1.2 (operation under examination).** Let $a_j\in\mathbb R^{1024}$
be a final visual token after per-token `post_layernorm`, and let
$A\in\mathbb R^{768\times1024}$ denote `visual_projection` in column-vector
notation. V4 maps $a_j\mapsto Aa_j$ for all tokens. CLS receives the usual
pooled map; non-CLS tokens receive its extrapolation to local states. For
text the analogous map takes normalized 768-dimensional token states through
`text_projection` to 768 dimensions. These dimensions are checked in the
[checkpoint configuration](https://huggingface.co/openai/clip-vit-large-patch14-336/raw/main/config.json).
The contract is to apply each final normalization once; an API returning
already normalized text states must not have final LayerNorm applied again.
“CLIP embedding” here means the projected vector before final unit-norm
normalization used for cosine similarity.

## 2. Why this is a reasonable hypothesis, and its limits

**Claim A1.3 (algebraic argument, not a semantic guarantee).** All visual
token positions use the same hidden coordinates, so the linear map $A$ is
well-defined for each of them. Keeping it frozen introduces no new pretrained
parameters and sends image tokens to the same output coordinate system as
the pooled image embedding. Text has its separately learned map to that joint
space. This motivates a shared representation for later learned fusion,
but equality of dimensions/coordinates does **not** prove local image–word
alignment, local calibration or preservation of task-relevant information.
The last hidden patch state also contains contextual information; it need
not represent only the pixels in its original patch.

**Claim A1.4 (verified prior use, with a bounded inference).** Zhou, Loy and
Dai, *Extract Free Dense Labels from CLIP* (ECCV 2022), §3.3, Eq. (4),
PDF pp. 6–7, reuse frozen value and output maps spatially for dense features
and discuss a ViT adaptation:
[paper](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136880687.pdf).
Their construction removes query/key attention in the final pooling path;
they also distinguish it from naively treating the original layer's outputs
as dense features. It is prior use of CLIP's learned maps for local prediction,
**not a validation of V4's exact last-hidden-state → post-LN → visual-projection
recipe**. Our inference is limited to architectural precedent. No MaskCLIP
performance result is claimed for V4, and this argument does not establish
that every non-EOS text token is a grounded word embedding.

**Claim A1.5 (information-loss limitation).** Because $A$ maps 1024 to 768
dimensions, rank-nullity gives $\dim\ker A\ge256$. For any $v\in\ker A$,
$A(a_j+v)=Aa_j$. A learned downstream linear map $W_v\in\mathbb R^{h\times768}$
therefore cannot recover a distinction solely along that nullspace:

$$
W_vA(a_j+v)=W_vAa_j.
\tag{A1.1}
$$

Whether this discarded variation matters to the task is unknown *(verify by
the proposed experiment)*. Conversely, a smaller frozen representation may
act as a useful constraint; that is also an empirical hypothesis *(verify)*,
not a demonstrated benefit on these datasets.

**Claim A1.6 (pooling commutes with projection, not LayerNorm).** Let $G$
be one four-patch pooling cell. Linearity gives

$$
\frac14\sum_{j\in G}Aa_j=A\left(\frac14\sum_{j\in G}a_j\right).
\tag{A1.2}
$$

Thus project-then-average and average-then-project give the same real-arithmetic
result **after** each token has received its post-LN. LayerNorm is nonlinear,
so moving the averaging before that normalization is a different experiment.
Finite-precision storage/accumulation can introduce rounding differences;
feature-parity tests must use a specified precision and tolerance.

## 3. Alternative: raw normalized tokens with a learned map

**Claim A1.7 (proposed controlled intervention, owner approval required).**
Cache $\tilde a_j\in\mathbb R^{1024}$: post-LN CLS plus the same 144 means
of post-LN patch tokens, **before** frozen visual projection. Replace the
image stream's learned map $W_v:768\to h$ by a single learned map
$B:1024\to h$, followed by the same normalization and dropout. Apply $B$ to
the CLS shortcut as well. Do not insert a 1024→768→h factorization, which
would test a different constraint. Keep text tokens and downstream modules
unchanged. Keep the original projected pooled CLS vector separately for
cross-fusion, the router and cosine similarity, so these inputs retain their
pretrained meaning and dimensions. The extra cached global vector is
accounted for below.

**Claim A1.8 (exact initialization control).** Initialize

$$
B_0=W_vA.
\tag{A1.3}
$$

For the same normalized/pooled raw tokens, $B_0\tilde a_j=W_v(A\tilde a_j)$.
With equal downstream parameters, biases and dropout masks, this reproduces
the projected-stream function at initialization in real arithmetic. The raw
map is then free to learn outside the constraint that its rows lie in the
row space of $A$. A random-init $B$ can be a separately registered secondary
control; it should not be conflated with the matched-function comparison.
Equivalent initial functions do not imply equivalent optimization: weight
decay and parameter-space updates act on different matrices.

## 4. Cost of the alternative

**Claim A1.9 (fusion arithmetic and parameters).** For one shared image
stream map with unchanged output width $h$, the projected baseline costs
$2P(768)h$ core FLOPs; the raw alternative costs $2P(1024)h$.
A6.1's convention gives

$$
\Delta F=2Ph(1024-768),\qquad
\Delta\#\theta=h(1024-768).
\tag{A1.4}
$$

At $P=145,h=512$ this is **38,010,880** extra core FLOPs per sample and
**131,072** extra trainable weights. Equal output-bias sizes cancel.
Cross-attention, downstream pooling, cross-fusion and router costs stay the
same under A1.7. If maps are not shared between experts, multiply the changed
map costs by the actual number of evaluations/parameter copies. Frozen CLIP
backbone work is unchanged. Literal cache extraction saves the 576 non-CLS
frozen projections ($2\cdot576\cdot1024\cdot768=905,969,664$ core FLOPs),
but still computes one projected CLS and performs pooling in 1024 dimensions.
This one-time saving is distinct from the extra per-epoch fusion cost; see
[A-6](A-6.md) for the extraction/online boundary.

**Claim A1.10 (cache bytes, no files generated).** With two bytes per stored
scalar, the image token arrays alone occupy $2P\cdot768=222,720$ versus
$2P\cdot1024=296,960$ bytes. That is **74,240** extra bytes per sample.
The raw branch also stores the original projected global CLS ($2\cdot768
=1,536$ bytes), already present as a token in the projected baseline. Thus
its incremental image-feature payload is **75,776** bytes per sample,
excluding metadata and unchanged text/global fields. These are analytic
payload sizes, not measured disk usage. The arithmetic and byte values are
reproduced in
[test_projection_derivations.py](../../tests/test_projection_derivations.py).

## 5. Experiment and decision rule — proposed, not run

**Claim A1.11 (matched comparison).** Register this raw-token comparison
with the ablations in #30 (internal),
including its selection rule and resource budget, before running it.
Use the same frozen checkpoint,
preprocessing, post-LN/pooling order, sample IDs, training/validation split,
expert architecture and shared paired seeds. Compare projected tokens with
A1.7's raw tokens initialized via A1.8. Keep the projected global CLIP
vectors, text path, chosen L/P/F variant and routing objective identical.
Use the same predeclared val-only search budget and stopping policy for both
representations; record learned-parameter count, extraction overhead, cache
size and fusion latency/FLOPs separately. Any small hyperparameter adaptation
needed for the new parameterization must be selected only on val under that
same budget. Record train–val gaps and per-seed paired metric differences.
No test access is authorized by this derivation, and no run is performed here.

**Claim A1.12 (what would change the choice).** Proposed decision: request an
owner-approved switch to raw tokens if the matched-initialization alternative
shows a repeatable validation gain in the predeclared selection metric across
paired seeds, with a paired-seed 95% interval for the gain wholly above zero,
and its extra cache/compute cost fits the agreed budget. The concrete metric,
minimum practically meaningful gain and budget must be frozen in the experiment
issue before running it; FHM's current selection metric is val AUROC, while
multiclass selection needs its own approved extension. If the intervals
include zero or gains do not justify the cost, retain the current projected
choice provisionally. A mixed dataset outcome requires owner review rather
than a universal alignment claim. This validation rule is a proposal, not a
paper significance result or an already approved change to defaults.

## 6. D-019 approved paper language and verification

**Claim A1.13 (paper wording, owner-approved D-019).** The
owner approved this wording (internal):

> We apply the frozen CLIP projection to normalized token states before
> downstream fusion. The projections were directly trained on pooled image
> and text representations; their tokenwise use is an approximation. Prior
> dense-CLIP work motivates reusing learned visual-language maps locally
> (MaskCLIP, §3.3), but does not validate our exact extraction recipe. We
> therefore treat local alignment as a design hypothesis and specify a
> controlled alternative using unprojected tokens with a learned map.

**Claim A1.14 (verification boundary).** Synthetic checks establish the
projection/pooling commutation, matched-function initialization, nullspace
limitation and arithmetic ledger. They establish no empirical model quality.
No result from the proposed experiment exists; all performance hypotheses
remain *(verify)*. Citations above were opened for this derivation; no
unopened citation is presented as verified.
