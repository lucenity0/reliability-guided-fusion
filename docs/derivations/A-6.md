## 1. Scope and counting convention

**Claim A6.1 (convention).** Report inference forward arithmetic per image–text
sample. A dense multiplication $(a\times b)(b\times c)$ is charged $2abc$
FLOPs (one multiply and one accumulate per inner term); a pure outer product
costs one multiplication per entry. This is the conventional contraction
count, not a literal instruction count (which can omit the first zero
accumulation). Bias additions, normalizations, activations, softmax, masking,
residual additions and memory operations are excluded from the **core** total
and itemized separately in A6.10. FLOPs do not measure latency. Training
backward and optimizer costs are not included and are not obtained by an
unqualified fixed multiple of inference cost.

**Claim A6.2 (symbols and established dimensions).** Let $P=145$, $L\le77$,
$N=P+L$, fusion width $h$, $H$ heads with $H\mid h$, head width $h/H$, FFN
width $f$, and $n_{layers}=N_x$. The stated defaults are $h=512$, $H=8$,
$f=2h=1024$, $n_{layers}=2$, joint feature width $d=768$, cross-fusion width
$n=32$ and $K=3$. Here $n=32$ is a spec starting point, not a verified
Hate-CLIPper reproduction setting. $L$ counts **executed** token positions;
padding masks do not reduce dense arithmetic. For a padded 77-position
implementation use $L=77$, even if fewer tokens are valid. The image CLS and
text EOS are included in $P,L$, respectively.

## 2. Cross-attention: every operation in both directions

**Claim A6.3 (one directional layer).** For a direction with $A$ query tokens
and $B$ context tokens, all input/output widths are $h$:

| Operation | Product shape or multiplicity | Core FLOPs |
|---|---|---|
| Query projection | $(A,h)(h,h)$ | $2Ah^2$ |
| Key projection | $(B,h)(h,h)$ | $2Bh^2$ |
| Value projection | $(B,h)(h,h)$ | $2Bh^2$ |
| Attention scores $QK^\top$ | $H$ products $(A,h/H)(h/H,B)$ | $2ABh$ |
| Weighted values | $H$ products $(A,B)(B,h/H)$ | $2ABh$ |
| Output projection | $(A,h)(h,h)$ | $2Ah^2$ |
| FFN expansion | $(A,h)(h,f)$ | $2Ahf$ |
| FFN contraction | $(A,f)(f,h)$ | $2Afh$ |

Adding these terms proves

$$
F_{dir}(A,B)=4(A+B)h^2+4ABh+4Ahf.
\tag{A6.1}
$$

**Claim A6.4 (bidirectional stack).** Set $(A,B)=(P,L)$ for image queries
and $(L,P)$ for text queries and sum; each direction reads previous-layer
states, as required by the simultaneous-update specification. With distinct
MHA weights in each direction, neither K/V nor output projections are omitted:

$$
\boxed{F_{cross}=n_{layers}\{8(P+L)h^2+8PLh+4(P+L)hf\}.}
\tag{A6.2}
$$

The head count cancels from dense products because $H(h/H)=h$. It still
affects score scaling/softmax work and the $2HPL$ attention-map entries per
bidirectional layer. MATH_SPEC §8's projections and FFN expressions match
this two-FLOP convention, but its $2\cdot2PLh$ scores-and-values expression
is half of the required $8PLh$. D-019 approves correcting that expression; these formulas account for both scores and values in both directions.

## 3. Input maps, cross-fusion and attention pooling

**Claim A6.5 (shared input projections and cross-fusion).** Applying each
$h\times d$ input matrix once to its modality stream costs

$$
F_{input}=2(P+L)dh,\qquad
F_{cf}=2dn+2dn+n^2=4dn+n^2.
\tag{A6.3}
$$

The second formula uses raw pooled $d$-vectors for $P_v\bar v,P_t\bar u$
and counts every entry of their $n\times n$ outer product. Flattening has no
arithmetic cost. Reuse the projected CLS/EOS entries for the unimodal
shortcuts and initial interaction states; do not charge a second projection
merely for indexing them. If an implementation recomputes the two shortcuts,
add $4dh$; if streams are independently projected per expert, count those
separate evaluations. The worked example assumes deterministic inference
with shared stream projections, not distinct training dropout masks.

**Claim A6.6 (literal pooling).** In §2's pooling equation assume dense
$W_k,W_o\in\mathbb R^{h\times h}$ and $q\in\mathbb R^h$. For $T$ tokens,
computing $W_kx_j,W_ox_j$ tokenwise costs $4Th^2$, query dot products cost
$2Th$ and the weighted value sum costs $2Th$:

$$
F_{AP}^{literal}(T)=4Th^2+4Th.
\tag{A6.4}
$$

There are four pools: image-only ($P$), text-only ($L$), interaction-image
($P$) and interaction-text ($L$). Their inputs differ, so their work is not
reused across experts. Total literal pooling cost is
$F_{pool}^{literal}=8(P+L)h^2+8(P+L)h$. Thus §8's $O((P+L)h)$ omits dense
maps if the §2 expression is executed literally.

**Claim A6.7 (exact reassociation, approved by D-017).** Compute
$u=W_k^\top q$ once, score tokens by $u^\top x_j/\sqrt h$, and then use
$\sum_j a_jW_ox_j=W_o(\sum_j a_jx_j)$. Linearity proves equivalence to
§2's pool, without changing the softmax or token mask. The core cost becomes

$$
F_{AP}^{assoc}(T)=4h^2+4Th,\qquad
F_{pool}^{assoc}=16h^2+8(P+L)h.
\tag{A6.5}
$$

This requires no tokenwise nonlinearity between $W_o$ and summation, as in
§2. The reassociation also preserves the differentiable function during
training, up to rounding, but it does not permit reusing $W_k^\top q$ across
optimizer updates without recomputing it. An inference compiler could fold
that constant further; (A6.5) conservatively recomputes it per pool per sample.
A $W_k$ bias adds the same offset to every score and cancels under softmax;
a $W_o$ bias can be added once because weights sum to one. The core table
omits biases either way. #31 must record which execution graph it measures.

## 4. Expert MLPs, router, heads and mixing

**Claim A6.8 (arbitrary widths give a closed form).** For affine-layer widths
$\mathbf w=(w_0,\ldots,w_m)$ define

$$
D(\mathbf w)=2\sum_{i=1}^m w_{i-1}w_i.
\tag{A6.6}
$$

Then $F_{experts}=D(2h,\ldots,h)+D(2h,\ldots,h)
+D(2h+n^2,\ldots,h)$, keeping separate internal widths if img/txt differ.
Let the router pooled projection widths be $a_v,a_t$, its input width
$R=a_v+a_t+K+1$ (two pooled embeddings, $K$ entropies and one cosine), and
its MLP end in $K$ outputs. Its core cost is

$$
F_{router}=2d(a_v+a_t)+D(R,\ldots,K).
\tag{A6.7}
$$

This assumes one affine pooled map per modality; for deeper $\phi^r$ maps
substitute their $D$ sums. Detached entropies still cost forward arithmetic;
detachment only removes backward paths. Cosine can be cached once with frozen
features. Its online dot/norm products would add approximately $6d$ core
FLOPs plus scalar square-root/division overhead.

**Claim A6.9 (classifier heads and all variants).** Let $q$ denote the number
of head outputs: $q=1$ for the existing binary single-logit task, or $q=C$
for a categorical head after owner approval. All $K$ expert heads cost
$F_{heads}=2Khq$. They remain necessary for entropy router inputs, including
under Variant F. For L or P the final weighted sum costs $2Kq$ under A6.1's
contraction convention; output sigmoid/softmax is separate. Therefore

$$
\boxed{F_{fusion}^{L/P}=F_{input}+F_{cross}+F_{cf}+F_{pool}
+F_{experts}+F_{router}+2Khq+2Kq.}
\tag{A6.8}
$$

For F replace $2Kq$ by $2Kh+D(h,\ldots,b_f)+2b_fq$, where $b_f$ is the
output width of $\operatorname{MLP}_f$ before its final classifier. This
retains the auxiliary expert heads. A shared affine F head is the special
case with $D=0,b_f=h$. D-017 specifies the complete F logit map as $h\to h\to q$, with GELU
and dropout between layers ($q=C$ for categorical, $q=1$ for binary shorthand).
Its dense cost is $2h^2+2hq$; in the generic formula this is
$D(h,h)+2hq$, not an additional C-row projection after an already C-row MLP.
Keep this cost separate from the L/P total.

## 5. Operations outside the core count

**Claim A6.10 (explicit exclusions for profiler reconciliation).** Define
$S(T)$ as the profiler's cost of one softmax of length $T$, $N_{LN}(h)$ as
one token LayerNorm, and $A(f)$ as the FFN activation on one width-$f$ token.
These costs depend on the chosen primitive conventions (exp, division,
reciprocal square root, fused kernels), so they are not silently zero in a
claim about full runtime. The additions to A6.8 include:

| Component | Additional work per sample |
|---|---|
| Cross attention, each bidirectional layer | $H[P S(L)+L S(P)]$ for softmax, $2HPL$ score scalings if scaling the score matrices, and mask additions |
| Pre-LN cross block | $2N N_{LN}(h)$ with normalized streams reused by both directions; add further normalizations if implemented separately |
| Residuals and FFN activations | $2Nh+N A(f)$ per bidirectional layer |
| Cross affine biases, if enabled | $[5h+f]N$ additions per layer (Q/K/V/O and two FFN maps) |
| Input projections | $N N_{LN}(h)$ and optional $Nh$ bias additions |
| Pooling | Two copies each of $S(P),S(L)$; score scaling/masking; optional biases according to the execution graph |
| Expert/router/F MLPs and heads | Sum output widths for each enabled bias; activation and normalization costs at their actual widths |
| Router uncertainty and output | $K$ predictive entropies, $S(K)$, and expert sigmoid or class softmax; one cached or computed cosine |
| Training losses | Main/auxiliary likelihoods, target softmax and KL, plus all backward work; absent from inference totals |

The $2N$ cross-block LayerNorm count uses one pre-attention normalized copy
of each stream plus one post-attention/pre-FFN copy. If directional modules
own separate context normalizers, their extra work must be added.
No current spec fixes all bias/activation details or a softmax FLOP convention.
The core total is fully specified under A6.1; a full-operator numeric total
and agreement with profiler coverage remain *(verify, #31)*.

## 6. Worked example at the stated dimensions

**Claim A6.11 (D-017 approved default dimensions).** Substitute
$P=145,L=77,d=768,h=512,H=8,f=1024,n_{layers}=2,n=32,K=3,q=1$.
D-017 approves img/txt MLPs $2h\to h\to h$,
interaction MLP $(2h+n^2)\to h\to h$, router projections $d\to h$ each,
and router MLP $(2h+K+1)\to h\to K$, with GELU and dropout between layers.
The approved headline uses reassociated pooling; literal pooling is reported
for reference. The core total excludes activations and dropout as in A6.1
(dropout is inactive at inference).

The approved and reference totals are approximately 2.1419 and 2.6033 GFLOPs using
$1\,\mathrm{GFLOP}=10^9$ FLOPs; neither includes A6.10 or frozen extraction.
For R3's overhead comparison, the approved L/P fusion head is approximately

## 7. Frozen CLIP forward: separate shared cost

**Claim A6.13 (verified architecture, separate token counts).** The
[released checkpoint configuration](https://huggingface.co/openai/clip-vit-large-patch14-336/raw/main/config.json)
checked for this derivation gives vision width $v=1024$, FFN width $4096$,
24 layers, 16 heads, patch size 14 and resolution 336; text width $t=768$,
FFN width $3072$, 12 layers, 12 heads and maximum length 77; joint width is
768. The frozen vision transformer processes
$S_v=(336/14)^2+1=577$ tokens, **not 145**. The reduction to 145 occurs only
after the frozen encoder. The
[reference implementation](https://github.com/openai/CLIP/blob/main/clip/model.py)
(`VisionTransformer.forward`, `encode_text`) projects CLS and EOS for its
standard pooled outputs. This source establishes architecture, not measured FLOPs.

**Claim A6.14 (closed-form backbone core).** For sequence length $S$, width
$w$ and FFN width $f_b$, one self-attention transformer block costs
$8Sw^2+4S^2w+4Swf_b$: Q/K/V/O, two attention products and two FFN products.
Let $L_b$ be the executed frozen-text length (usually padded to 77, even if
fusion later trims tokens). For a three-channel image and patch size $p=14$,

$$
\begin{aligned}
F_{vision}&=2(S_v-1)(3p^2)v
+24[8S_vv^2+4S_v^2v+4S_vv(4096)]+2vd,\\
F_{text}&=12[8L_bt^2+4L_b^2t+4L_bt(3072)]+2td.
\end{aligned}
\tag{A6.9}
$$

The first term is patch convolution and the final terms are the standard
pooled projections. Text uses dense square attention despite its causal mask;
a kernel that skips masked products requires a different executed-work ledger.
Token embedding lookup, positional additions, LN, nonlinearities and normalized
image–text similarity are outside this core count. Contrastive batch all-pairs
logits are not part of single-sample feature extraction.
At $S_v=577,L_b=77$, (A6.9) yields **381,919,789,056** vision and
**13,299,683,328** text FLOPs: **395,219,472,384** in total (about 395.2195
GFLOPs). These are analytic values reproduced in the test, not measurements.
Every method using the same CLIP image/text pair pays this common extraction
cost once; a unimodal-only encoder pass naturally uses only its own tower.

**Claim A6.15 (dense-cache overhead, also separate).** The literal §1 cache
recipe additionally projects all 576 non-CLS image tokens and $L_b-1$
non-EOS text tokens. Relative to the pooled backbone core this adds

$$
F_{dense-extra}=2(576)vd+2(L_b-1)td,
\tag{A6.10}
$$

or **905,969,664** image and **89,653,248** text FLOPs at the above dimensions.
A 2×2 mean over 576 projected patches adds $144d(3+1)=442,368$ scalar
operations (three additions and one scaling per output coordinate). Vision
post-LN on extra tokens is separate; text final LN already covers its stream.
This overhead belongs to dense feature caching, not to the common pooled
CLIP baseline. Projection may instead be moved after patch averaging by
linearity once per-token post-LN has been applied; that alternate execution
must not be charged as (A6.10). Cached head training/inference pays neither
backbone nor dense extraction again. Uncached deployment adds the applicable
extraction ledger to A6.8 and the separately counted overheads.
